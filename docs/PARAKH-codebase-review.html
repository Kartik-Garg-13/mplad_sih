The one-sentence idea

MPLADS gives every Member of Parliament ₹5 crore a year for local works. The public data on those works exists, but sanctions, payments and completion status sit in separate spreadsheets that are never joined — so nobody can see the scheme whole.

The trap in this problem statement

The obvious build is a model that scores each MP and names the worst ones. That tool would be a defamation engine: it would publish accusations about named public figures from data that cannot support them. An MP with more sanctioned works collects more flags for that reason alone.

PARAKH is built the other way round. Flags attach to works, never to people. Every flag shows its evidence and a plausible innocent explanation side by side, and a human decides. The product ranks works and agencies; it never ranks members. That restraint is enforced by tests that fail the build, not promised in a slide.

How the pipeline runs

Everything is computed in advance, in a batch job. Nothing is calculated while a user waits, and no model runs at request time. This is why the whole thing works offline and gives the same answer twice.

STAGE 1

Ingest

eSAKSHI CSV exports, downloaded by hand — no scraper. Polars cleans and joins them into Parquet files.

STAGE 2

Detect

All 13 detectors run over the cleaned data. Each returns rows of work_id, detector, tier, evidence. Results are written into DuckDB.

STAGE 3

Serve

FastAPI reads that database. Every endpoint is a SELECT — the API cannot compute a detector even if asked.

STAGE 4

Review

A Next.js queue. A reviewer reads the evidence, reads the innocent explanation, and closes the flag with a note.

Why batch, and not a live model

Three reasons, and a judge may push on this. Reproducibility: the same input always yields the same flags, so anyone can re-run the pipeline and get your exact numbers. Auditability: a flag you can reproduce is a flag you can contest — which matters when the subject is public money. Cost: no GPU, no per-query charge, no internet at run time.

Rebuild command: python -m parakh.pipeline → python -m parakh.database · takes seconds

Why there are two tiers

The tier is the single most important idea in the project, and it is always visible next to every flag. It tells the reviewer how much the flag is worth.

TIER A  The record contradicts itself

Arithmetic or logic that a human can check by hand, on that one row, with no context at all. A payment larger than the sanction it belongs to. A completion date before the sanction date. The same work ID twice. You do not need statistics to agree these are wrong — you need a calculator.

TIER B  The work stands out from its peers

Statistical. This work costs far more than similar works in the same category and state, or has been open far longer than similar works take. Tier B is a reason to look, never a finding. A flyover in Mumbai and a borewell in Koraput are both "works" — an absolute outlier is meaningless, so every Tier B flag states its peer group and how many peers it had.

The abstention rule: if a peer group has fewer than 30 members, the detector returns nothing rather than guessing. Saying "I don't know" is a feature — with 8 peers, an outlier is noise.

Tier A — the five integrity checks

Deterministic. Each either fires or doesn't. "Fires" below is the real count on the current corpus.

A1TIER A0 flags

Ledger contradiction

What it looks for
Three separate impossibilities: payments recorded against a work add up to more than the work was sanctioned for; a sanction amount that is zero or negative; or a completion date earlier than the sanction date.
How it works
Sum the payments per work, join to the sanction, compare. A tolerance of ₹1 is allowed — two "excess" cases in the real data turned out to be about 0.0000000001 rupees of floating-point rounding, not overspending.
Why it currently fires zero times
Genuinely no contradictions of this kind exist in this export. That is a real result, not a broken detector — and a good thing to say out loud rather than hide.
A2TIER A39 flags

Phantom completion

What it looks for
A work marked "Work Completed" where almost nothing has actually been paid out — either zero rupees, or under 5% of the sanctioned amount.
How it works
Sum payments per work, keep only the completed ones, compare against the 5% threshold.
Innocent explanation shown alongside
The work may have drawn on state or local-body co-funding outside MPLADS, come in under budget, or have its final settlement queued for the next disbursement cycle.
A3TIER A0 flags

Duplicate record

What it looks for
The exact same work ID appearing more than once in the source export.
The version we deleted
Originally this also flagged different IDs sharing description, location, agency and amount within 90 days. Tested on real data: it fired 8,126 times, almost entirely on legitimate batch orders — one MP requesting the same standard item at many schools with one copy-pasted description. The largest genuine group was 118 identical high-mast lights from a single MP. We removed it rather than ship a detector that is wrong 8,000 times.
Why it currently fires zero times
The export has no repeated IDs. Also a real result.
A4TIER A636 flags

Orphan sanction

What it looks for
Money was sanctioned, but the record has no implementing agency, no state, or no category — nobody is recorded as responsible for spending it.
How it works
A null check on those three fields, restricted to works that actually have a sanction amount.
Innocent explanation shown alongside
Usually a blank field at upload time or a column dropped during a system migration, rather than a work genuinely assigned to nobody.
A5TIER A12,681 flags

Unverified completion

What it looks for
A work marked complete with no photograph on file.
The honest caveat
Only 23.8% of works in this corpus have photo evidence at all, so this fires often and is weak on its own. It is useful in combination with other flags, not as a standalone accusation — and the product says so.
Innocent explanation shown alongside
Older works predate the portal's image-upload requirement, or an upload simply failed at submission.

Tier B — the eight statistical checks

All peer-relative. Every one states its peer group and n in the evidence sentence, and abstains below 30 peers.

B1TIER B8,914 flags

Peer cost outlier

What it looks for
This work cost far more (or far less) than similar works — same category, same state, same financial year.
How it works
A robust z-score above 3.5. See the algorithms section for what "robust" means and why the ordinary version fails here.
Innocent explanation shown alongside
Difficult terrain, urban land costs, or several works clubbed into one entry can all put real costs above the median.
B2TIER B550 flags

Cost-per-unit outlier

What it looks for
Not total cost but unit price — rupees per metre of road, per streetlight, per litre of tanker capacity — against peers in the same category, unit and state.
The honest caveat
Only about 5% of works have a quantity we can extract at all, because MPLADS descriptions are location narratives ("from X's house to Y's house"), not specifications. Low coverage is reported, not hidden. The peer group deliberately drops financial year — coverage is already thin and adding it would push most groups below the n=30 floor.
B3TIER B7,774 flags

Stalled work

What it looks for
A work still not finished, open longer than 95% of comparable works took to complete.
How it works
The threshold is learned from the data, never hard-coded. For each category × state, take every work that did finish, compute the 95th percentile of days-to-complete, then apply that number to the ones still open.
Innocent explanation shown alongside
Land-acquisition disputes, contractor litigation, monsoon delays, or an agency handover — administrative friction, not abandonment.
B4TIER B6,304 flags

Threshold bunching

What it looks for
An agency whose sanctions cluster suspiciously just below a round-rupee approval tier — ₹4.9 lakh when ₹5 lakh needs a higher sign-off.
How it works
For seven round thresholds, count how many of an agency's sanctions land within 5% below each one, and compare that share against the national share in the same band. Flags when the agency's share is over 10% and more than 3× the national rate.
The version we deleted
The plan also called for a Benford's-law digit test per agency. Built, then removed — twice. Against the theoretical Benford curve it flagged all 333 eligible agencies, because sanction amounts are policy-chosen round figures, not the organically-arising quantities Benford describes. Rebuilding it against the corpus's own digit pattern still flagged all 333, because agencies genuinely specialise in different work types with different price points. A detector that fires on everything says nothing.
B5TIER B2,347 flags

Work splitting

What it looks for
One big job broken into several small ones to stay under an approval limit: three or more similarly-worded works, same agency and district, within 30 days, all comparable in size.
How it works
TF-IDF similarity above 0.85 links pairs; union-find merges those pairs into clusters. A cluster only counts if no single work exceeds half the cluster's total — that is what separates "split job" from "one real work plus small extras".
Innocent explanation shown alongside
An area-wide rollout — the same standard item installed at several sites as one coordinated programme.
B6TIER B3,241 flags

Agency concentration

What it looks for
One agency handling an unusually large share of a single MP's total sanctioned value, compared with how concentrated other MPs' relationships normally are.
The bug real data exposed
First version flagged nothing at all. Reason: 187 of 677 MPs route 100% of their value through one agency — because their constituency sits inside one district, which has exactly one agency. No choice was ever available. That pinned the 95th percentile at 1.0, so nothing could exceed it. Fix: only consider MPs who actually used 2+ agencies. A share is only meaningful when there was something to concentrate away from.
B7TIER B3,436 flags

Year-end bunching

What it looks for
An MP with a disproportionate share of a year's sanctions crammed into the final 90 days of the financial year — the classic budget dump.
Two things we changed after seeing real data
The plan said "final 90 days of the term", but the 18th term has not ended, so that has no anchor. Financial-year-end does, and year-end fund-dumping is a recognised pattern in its own right. Second, the minimum was raised from 10 sanctions to 40: MPs submit in a few large batches, so at n=10 whether a batch lands in the window is nearly a coin flip — 7.7% of groups sat at exactly 100%, pinning the percentile at the ceiling again.
Innocent explanation shown alongside
Year-end surges track when state treasuries release funds and when utilisation targets are reported — a budget-cycle artefact common across all MPs.
B8TIER B9,634 flags

Near-duplicate funding

What it looks for
Two different work IDs whose descriptions are 90%+ similar, in the same district, recommended within 180 days — possibly the same physical asset funded twice.
The clever bit
Matches at 99.9%+ similarity are excluded, not included. Near-verbatim text means a copy-pasted template for a legitimate bulk order. A genuine accidental double-entry, typed independently by two people, lands just below a perfect match. The signal is in the band, not at the top.
Why the 180-day window
Without it, same-district-and-similar-wording matched 13,162 pairs — about 20% of the corpus, implausible for double-funding. This one is a judgment call about a reasonable window, not a number derived from the data, and the code says so.

The algorithms, in plain words

Six techniques carry the whole system. None of them is a black box, and that is deliberate.

Robust z-score (median absolute deviation)

An ordinary z-score asks "how many standard deviations from the mean?" — but the mean and standard deviation are themselves dragged around by the very outliers you are hunting. One ₹5 crore entry inflates the average so much that it stops looking unusual.

The robust version uses the median instead of the mean, and the median absolute deviation instead of the standard deviation. Both ignore extremes, so a genuine outlier cannot hide by distorting its own yardstick. The constant 0.6745 rescales it so the number is comparable to a normal z-score.

The real-data problem, and the three-level fallback. MPLADS peer groups often have most works at one exact round figure — so the MAD is zero, and dividing by it breaks. Level 2 falls back to the interquartile range. When 75%+ share one value, even that is zero; level 3 then abstains unless the work is at least 2× away from the median. Before this fix, B1 flagged 3,172 works whose own evidence said "1.0× the peer median" while calling them extreme outliers.

Used by B1, B2 · src/parakh/peer_stats.py

TF-IDF + cosine similarity

How do you tell a computer two descriptions mean the same thing? TF-IDF turns each description into a vector of word weights, where a word counts for more if it is rare across the corpus — "construction" is everywhere and counts little; "cremation" is rare and counts a lot. Cosine similarity then measures the angle between two vectors: 1.0 is identical, 0 is nothing in common.

Used by B5 (0.85 threshold), B8 (0.90 threshold) · src/parakh/text_similarity.py

Union-find (disjoint set)

Similarity gives you pairs, but work-splitting is about groups. If A resembles B and B resembles C, all three belong in one cluster even if A and C were never directly compared. Union-find merges pairs into groups in near-constant time.

Used by B5 · _UnionFind in tier_b.py

Empirical percentiles (P95, P75)

Rather than declaring "90 days is too slow", the code asks the data: of every comparable work that actually finished, how long did the slowest 5% take? That becomes the threshold. It adapts per category and state automatically — a borewell and a bridge get different clocks — and it is defensible, because it came from the domain rather than from us.

Used by B3 (P95) and the stall model's labels (P75)

Louvain community detection

Build a graph where MPs and agencies are dots and a shared work is a line between them. Louvain finds communities — clusters more densely connected inside than outside — by repeatedly moving nodes to whichever neighbouring group most improves the clustering, then collapsing each group into a single node and repeating.

Used by the network graph page · NetworkX · src/parakh/graph.py

LightGBM gradient boosting

The one genuine machine-learning model, and it does a narrow job: predict which currently-normal-looking works are most likely to stall. Gradient boosting builds many small decision trees in sequence, each correcting the previous one's mistakes.

Its labels are careful. Works that finished get a real label. Works already past the P95 with no completion are labelled stalled. Works still inside the normal window are excluded from training — their outcome genuinely isn't known yet, and labelling them either way would be guessing.

Used by the at-risk page · src/parakh/stall_model.py

The five validation methods

There is no labelled dataset of "known bad MPLADS works" to test against, so a single accuracy number is impossible. Five independent methods attack the problem from different angles — and three of them returned results that are unflattering. All five are published as they came out.

1  Synthetic injection — the one hard number

Clone real works, deliberately corrupt them in known ways, mix them back in, and see how many the detectors catch. Each injected row keeps its real state, category and agency so it lands in a real peer group.

2  Known-case backtest — returned nothing, and we explain why

Take MPLADS irregularities documented in CAG audits and press coverage, and check whether those works rank highly here. Two real cases were researched. Neither matched.

The reason is structural, not a search failure. CAG compliance audits examine works that are years old and already executed — the audit itself takes years to publish. This corpus is the 18th term only: recommended and sanctioned in the last one to three years, largely still in progress. A match against a finalised CAG finding should not exist yet. The method becomes checkable when audits of 18th-term spending are published, and not before.

Case 1: Indoor Sports Hall, Andaman PWD (CAG Report 22 of 2025) — the audited agency does not appear in this corpus at all · Case 2: outside this term by construction

3  Manual adjudication — 0 of 50 were irregular

The top 50 flagged works were reviewed by hand and classified three ways. The result: 0 plausibly irregular, 1 undecided, 49 explained as benign.

Every one of the 50 belonged to one of eight batch-procurement clusters — streetlights, water tankers, library books, multi-gym sets. That is not a failure of the detectors; it is a finding about the ranking. A plain "most flags first" sort promotes large legitimate batches over rarer single-flag anomalies. Reporting the honest denominator is the point of the method.

Largest cluster: 47 near-identical 3,000-litre water tankers in Fazilka, Punjab (~₹2.40L each)

4  Stability under resampling — B7 is fragile, and we say so

Re-draw the corpus at random with replacement, re-run each detector, and measure how much the flagged set overlaps the original (Jaccard overlap). A stable detector flags roughly the same works whichever sample it sees.

Read the numbers against 0.632, not 1.0. A same-size bootstrap sample only ever contains about 63.2% of the original distinct rows, so even a perfect detector cannot score near 1.0. Knowing that ceiling is what makes 0.589 "excellent" rather than "barely more than half".

B5 and B8 are excluded: resampling duplicates rows verbatim, which a text-similarity detector would read as near-duplicates — an artefact of the method, not the detector. Tier A is excluded: nothing is fitted to the sample.

5  Stall model — time-split, never random

The model is tested by training on earlier works and predicting later ones — a time split. A random split would let the model peek at works from the same period it is predicting, which flatters the score and would never happen in deployment.

PR-AUC 0.569 against a base rate of 0.386 — the model does meaningfully better than guessing. ROC-AUC 0.710.

52,550 training works · 13,163 test works · calibration curve published on the validation page

The three things beyond the flag list

Agency network graph

Every MP–agency relationship as a graph, clustered into communities. Two real anomalies come out of it: thin-file agencies (very few works but disproportionate money) and 19 agency names appearing under more than one state — most likely a data-entry inconsistency, but worth a look.

One planned signal was cut: "agencies reaching abnormally many constituencies". The top of that list was simply the big district administrations — Kannur, Kottayam, Palakkad, Bangalore Urban — which legitimately span several seats. Shipping it would have read as not understanding the domain.

Constituency scorecard

Framed explicitly as district delivery performance, not integrity. This is the one place the data comes closest to being about people, and the framing is deliberately narrow for exactly that reason.

The grounded assistant

An "Ask about this data" panel on every page. There is no language model behind it — a question either matches a fixed set of intents and is answered from rows read out of the database, or it is told what can be asked instead. It runs offline and cannot invent a figure.

One intent exists only to refuse: asked to rank members by flag count, it declines and explains why. A generative assistant would happily answer that question, which is precisely why there isn't one.

What we did not build

The original plan had a third tier: an Isolation Forest, a Local Outlier Factor model, and a composite 0–100 "Review Priority Score" ranking every work on one number. None of it shipped. 13 of 16 planned detectors are built.

This is stated on the product's own Methodology page, not only in a deck. A tool whose entire argument is restraint has to apply that restraint to its own claims first. Say this before a judge finds it — it is a strength, not an admission.

Questions judges will ask

"So can you tell me which MP is the most suspicious?"
No — and that is the design, not a limitation. Flags attach to works. An MP with more sanctioned works collects more flags for that reason alone, so a count of flags measures activity, not conduct. The tool ranks works and agencies; it never ranks members. The assistant refuses this question in code, and a test in the build enforces it.
"Two of your detectors fire zero times. Are they broken?"
No — A1 and A3 find no ledger contradictions and no repeated work IDs in this export. That is a real result about clean data. We report the true count of registered detectors rather than only the ones that happened to fire, because quietly dropping the zeroes would overstate what the corpus contains.
"Your manual review found 0 of 50 were actually irregular. Doesn't that mean it failed?"
It means the ranking needs work, and we would rather report that than hide it. The detectors correctly identified unusual patterns; a plain "most flags first" sort then promoted large legitimate batches above rarer single-flag anomalies. Publishing the honest denominator is what makes the other four validation methods believable.
"Where is the AI? This looks like SQL."
There is machine learning — LightGBM for stall prediction, TF-IDF and cosine similarity for text, Louvain for community detection, robust statistics throughout. But for money and public figures, the reviewer must be able to check the arithmetic by hand. A model that cannot explain itself cannot be contested, and an accusation nobody can contest is the failure mode this problem statement warns about.
"Why is one of your stability scores only 0.056?"
B7, year-end bunching, is genuinely fragile at this peer-group size — its threshold sits close to where small sampling changes flip which MPs cross it. We publish it rather than quietly drop the detector or the metric. Note also that the ceiling is 0.632, not 1.0, because a bootstrap sample only contains about 63% of distinct rows.
"How do I know the numbers on your slides are real?"
Clone the repository, run two commands, and the pipeline rebuilds every figure from the published source data. Same input, same flags, every time — there is no random seed or live model call anywhere in the detection path. 175 automated tests cover the detectors, the validation methods and the restraint rules themselves.
"What would you build next?"
Fix the ranking that the manual adjudication exposed — cluster-aware ordering so one 47-tanker batch occupies one slot instead of fifteen. Then the retired Tier C, but only with a peer-group-controlled design, since the naive version flagged all 333 agencies. Both are already written down in the product, not invented for this answer.
